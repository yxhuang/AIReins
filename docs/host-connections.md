# 本机与远程 Workbench

每台电脑独立运行 Workbench 和所在 WSL/Linux 的 Agent。点击左上角 **wb｜本机/远程机器名** 整体按钮（文字沿用 Workbench 字体样式），菜单收窄为300px，选择「机器名（本机）」或已保存的 Tailscale 机器；按钮保留 wb 标志，使用描边、高光、轻投影和按压反馈，去掉小箭头。窗口标题显示 `Workbench · 本机` 或 `Workbench · 远程 <机器名>`，待处理闸门计数仍保留。通过 Tailscale 地址访问，即使是这台机器自身，也按远程入口显示。

## 另一台电脑安装

在它自己的 WSL/Linux 中 clone 本仓库，进入仓库运行 `bash install.sh`；依赖要求见 [新电脑安装](../README.md#新电脑安装)。脚本安装 `wb` 命令，WSL 下也安装 Windows 托盘与快捷方式；完成后手动固定到任务栏。Windows Tailscale 已安装、登录并运行时，脚本自动生成缺失的 `~/.workbench/remote.json`（本机 MagicDNS origin、本机用户白名单、8793 端口、权限 600、远程终端默认关闭），已有配置只校验并打印 origin、不覆盖。登录任务缺失时弹出一次 UAC，允许后安装 Windows 远程网关及 Serve；已有任务打印状态并跳过，拒绝或失败时打印手动命令且继续本机安装。新配置遇到已运行 WB 时提示「运行 wb restart 使远程入口生效」，不会自动重启；未运行则按现有冒烟流程处理。

`git pull` 后重跑同一命令即可更新；`bash install.sh --check` 只读报告 remote.json、Serve 与计划任务状态，不写文件或弹 UAC。非 WSL、无 Tailscale 或未登录时跳过远程配置，登录后可重跑。CLI 安装、登录和本地工作目录属于那台电脑，clone 仓库不会复制这些状态。远程终端默认关闭，如需远程终端改为 `true` 后 `wb restart`。代理客户端 等系统代理须把 `*.ts.net` 加入绕过，否则浏览器可能报 `ERR_TUNNEL_CONNECTION_FAILED`。

## 双向连接

1. 两台电脑各自准备可访问的 Tailscale WB HTTPS 地址。WSL 新电脑可由 `bash install.sh` 自动配置；其他环境参考 [后端远程入口配置](../server/README.md#远程入口配置-workbenchremotejson)。Serve、身份白名单与 Host/Origin 校验继续生效，每台电脑使用自己的入口。Windows 登录后按需启动参考 [REMOTE.md](../deploy/windows/REMOTE.md)。
2. 在每台电脑的本机 WB 中，点击左上角 wb 品牌按钮，从「Tailscale 上的其他电脑」选择对方，即可保存地址并切换；↗ 则保存并在独立窗口打开（Chrome App 窗口内打开的新窗口与 WB 在任务栏归为一组；中键仍开浏览器标签页）。每次打开菜单只发现一次，列出同一 tailnet 中尚未保存的 Windows/Linux/macOS 电脑，在线优先；离线电脑置灰并标「离线」，仍可点击。「设置 → 主机与连接」和「管理主机…」也可手动添加：支持完整地址（例如 `https://other-pc.tailxxxx.ts.net`）、裸 MagicDNS 名（可带末尾 `/` 或 `.`）、Tailscale IPv4/IPv6 和机器名。裸 MagicDNS 直接补全 HTTPS；IP 或机器名在点击添加时查询 Tailscale 设备，机器名不区分大小写，可匹配设备名称或 MagicDNS 首段。补全成功会显示「已补全为 …」；找不到时提示原因且不保存，多台同名时提示改用 IP 或完整地址，避免添加错电脑。最终保存的地址仍只接受完整 HTTPS MagicDNS origin，不带路径、查询、fragment、账号密码或自定义端口，最多保存 16 台。
3. 点击品牌按钮选择目标，当前页面整页跳到目标 WB；每行的 ↗ 在普通浏览器中另开标签页，在 WB App 窗口中左键另开 popup 窗口，同时查看两台电脑。中键及修饰键沿用浏览器默认行为。
4. 从本机 WB 进入远程时，带上发起浏览器的本机返回入口，远程菜单可选「本机」返回。直接在手机或独立浏览器打开远程地址时，没有本机返回入口。

本机机器名来自后端 `/api/meta.hostName`，优先使用该主机远程配置里的 Tailscale 名称，否则使用实际系统 hostname。该后端变更需重启后加载；旧后端未提供名字时暂显示「本机」。来源名字随连接上下文带到远程，防止把目标主机的名字写成来源本机。

主机列表按浏览器及 origin 保存在 `localStorage`，不写仓库或三家 CLI 配置。切换时仅通过 URL fragment 传递经过校验的主机地址和返回入口，在加载会话前消费并移除；不携带会话、草稿、文件或凭证。合并优先保留目标源已有地址，最多保存16台；超额传入地址不会覆盖已有条目，并弹出未保存提示。列表已满时直接打开另一台主机，该主机仍显示为当前菜单项，但明确标为暂未保存。浏览器禁止存储时保留本页状态并显示保存失败提示，刷新后的持久性不保证。

切换后，会话、历史、文件、工作目录、权限和终端都属于目标机器。切换不迁移任务，也不发送中断、释放或重启命令；正常运行的后台任务继续在原主机上执行。文件正在保存时阻止当前页面切换；未发送输入（包括新建会话的首条消息）/附件确认后才能切走，未保存文件沿用浏览器离页确认。新窗口打开保留原页面；主机菜单的上下方向键同时覆盖当前页切换和新窗口操作。

发现仅表示设备在 Tailscale 上登记，不代表安装或运行了 WB；不做跨源探测。后端只读运行 `tailscale status --json`，优先 PATH 中的 `tailscale`，WSL 未找到时使用 Windows 安装路径；命令超时约 5 秒且输出有上限，未安装、未运行或读取失败时不显示发现列表。目标电脑需要开机、联网、允许访问且 WB 可用；Tailscale 本身不唤醒停止的 WSL。连接失败停留在目标地址的错误页面，浏览器后退可以返回来源，不自动改为本机执行。远程终端和原生 Windows 文件选择沿用目标已有能力配置。

## Chrome 标签页与 WB 窗口互转

WB App 窗口的主机菜单底部显示「在 Chrome 中打开」（其他浏览器显示「在浏览器中打开」），将当前主机和会话作为普通标签页打开，原 WB 窗口保留。

普通桌面标签页在本机 `/api/meta.capabilities.appWindow` 为 true 时显示「在 WB 窗口中打开」。点击后，本机后端用 Windows Chrome 的 `--app=http://127.0.0.1:<本机端口>/#wb-goto=<目标>` 打开窗口，再尝试关闭当前标签页。浏览器拒绝关闭时保留标签页，不显示关闭错误。目标的路径、查询及会话 hash 会在加载会话前还原；localhost 和开发入口的路径还原到 App 的 127.0.0.1 origin，保证启动 host 和根路径与托盘一致。

「在 WB 窗口中打开」只显示在本机普通桌面标签页；远程页、手机、非 WSL 或未找到 Windows Chrome 时不显示。后端启动目标只接受本机 WB 入口；主机切换仍只携带原有连接上下文，不传递 App 能力位或页面路由。

打开失败时标签页保留并提示原因；文件正在保存时阻止互转，未发送输入或附件需确认，未保存文件沿用浏览器离页确认。后端代码需要用户择时重启才生效。

自动测试使用假 launcher，不真实运行 Chrome；真实 Windows Chrome 启动、window.close 和任务栏归组仍需实机验收。

## 验收边界

自动回归覆盖地址校验、名称/标题、往返上下文、目标主机地址合并、手机直接访问与存储不可用。Linux Chromium 的桌面夹具已走到跨源往返、新标签、草稿/文件保护，完整夹具因目录及设置存储的模拟数据问题两次中断后暂停；补齐 mock 后保留脚本等待明确续接。真实两机/Tailscale、Windows Chrome App 窗口与手机 PWA 的跨域打开行为仍须实际验收。
