# 本机与远程 Workbench

每台电脑独立运行 Workbench 和所在 WSL/Linux 的 Agent。点击左上角 **wb｜本机/远程机器名** 整体按钮（文字沿用 Workbench 字体样式），菜单收窄为300px，选择「机器名（本机）」或已保存的 Tailscale 机器；按钮保留 wb 标志，使用描边、高光、轻投影和按压反馈，去掉小箭头。窗口标题显示 `Workbench · 本机` 或 `Workbench · 远程 <机器名>`，待处理闸门计数仍保留。通过 Tailscale 地址访问，即使是这台机器自身，也按远程入口显示。

## 另一台电脑安装

在它自己的 WSL/Linux 中准备 Node 22 和与本机相同的 Agent 环境，clone 本仓库，运行 `npm install`。已有 `wb` 命令时运行 `wb`；没有全局入口时，在仓库目录运行 `bash bin/workbench`。CLI 安装、登录和本地工作目录属于那台电脑，clone 仓库不会复制这些状态。

## 双向连接

1. 两台电脑各自准备可访问的 Tailscale WB HTTPS 地址。沿用 [后端远程入口配置](../server/README.md#远程入口配置-workbenchremotejson) 的 Serve、身份白名单与 Host/Origin 校验；新增电脑须配置它自己的入口。Windows 登录后按需启动参考 [REMOTE.md](../deploy/windows/REMOTE.md)。
2. 在每台电脑的本机 WB 中，打开「设置 → 主机与连接」，或品牌菜单的「管理主机…」，添加对方的地址，例如 `https://other-pc.tailxxxx.ts.net`。只接受完整 HTTPS MagicDNS origin，不带路径、查询、fragment、账号密码或自定义端口。名字直接读取域名中的 Tailscale 机器名，最多保存 16 台。
3. 点击品牌按钮选择目标，当前页面整页跳到目标 WB；每行的 ↗ 可另开标签页，同时查看两台电脑。
4. 从本机 WB 进入远程时，带上发起浏览器的本机返回入口，远程菜单可选「本机」返回。直接在手机或独立浏览器打开远程地址时，没有本机返回入口。

本机机器名来自后端 `/api/meta.hostName`，优先使用该主机远程配置里的 Tailscale 名称，否则使用实际系统 hostname。该后端变更需重启后加载；旧后端未提供名字时暂显示「本机」。来源名字随连接上下文带到远程，防止把目标主机的名字写成来源本机。

主机列表按浏览器及 origin 保存在 `localStorage`，不写仓库或三家 CLI 配置。切换时仅通过 URL fragment 传递经过校验的主机地址和返回入口，在加载会话前消费并移除；不携带会话、草稿、文件或凭证。合并优先保留目标源已有地址，最多保存16台；超额传入地址不会覆盖已有条目，并弹出未保存提示。列表已满时直接打开另一台主机，该主机仍显示为当前菜单项，但明确标为暂未保存。浏览器禁止存储时保留本页状态并显示保存失败提示，刷新后的持久性不保证。

切换后，会话、历史、文件、工作目录、权限和终端都属于目标机器。切换不迁移任务，也不发送中断、释放或重启命令；正常运行的后台任务继续在原主机上执行。文件正在保存时阻止当前页面切换；未发送输入（包括新建会话的首条消息）/附件确认后才能切走，未保存文件沿用浏览器离页确认。新标签打开保留原页面；主机菜单的上下方向键同时覆盖当前页切换和新标签操作。

目标电脑需要开机、联网、允许访问且 WB 可用；Tailscale 本身不唤醒停止的 WSL。连接失败停留在目标地址的错误页面，浏览器后退可以返回来源，不自动改为本机执行。远程终端和原生 Windows 文件选择沿用目标已有能力配置。

## 验收边界

自动回归覆盖地址校验、名称/标题、往返上下文、目标主机地址合并、手机直接访问与存储不可用。Linux Chromium 的桌面夹具已走到跨源往返、新标签、草稿/文件保护，完整夹具因目录及设置存储的模拟数据问题两次中断后暂停；补齐 mock 后保留脚本等待明确续接。真实两机/Tailscale、Windows Chrome App 窗口与手机 PWA 的跨域打开行为仍须实际验收。
